### 生成其他迭代器的方法

`Iterator` 特性中定义的其他方法，被称为 _迭代器适配器_，允许您将迭代器转换为不同类型的迭代器。您可以将多个迭代器适配器的调用链接在一起，以一种易于理解的方式执行复杂操作。但是由于所有迭代器都是惰性的，您必须调用一个消耗适配器方法以从迭代器适配器的调用中获得结果。

下面的代码片段展示了调用迭代器适配器方法 `map` 的示例，它接收一个闭包以对每个项进行调用以生成一个新的迭代器。这里的闭包创建了一个新的迭代器，其中向量中的每个项都增加了1。然而，这段代码会产生一个警告：

```rust
    let v1: Vec<i32> = vec![1, 2, 3];

    v1.iter().map(|x| x + 1);
```

##### 调用迭代器适配器 map 以创建一个新迭代器

我们收到的警告是这样的：

```text
warning: unused `Map` that must be used
 --> src/main.rs:4:5
  |
4 |     v1.iter().map(|x| x + 1);
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = note: `#[warn(unused_must_use)]` on by default
  = note: iterators are lazy and do nothing unless consumed
```

上一个例子中的代码没有执行任何操作；我们指定的闭包从未被调用。警告提醒我们原因：迭代器适配器是惰性的，需要在这里消费迭代器。

为了解决这个问题并消费迭代器，我们将使用 `collect` 方法，该方法在 Rust 书的 [第 12 章](https://doc.rust-lang.org/stable/book/ch12-01-accepting-command-line-arguments.html) 中与 `env::args` 一起讨论。此方法消耗迭代器并将结果值收集到一个集合数据类型中。

在下面的示例中，我们将通过调用 `map` 返回的迭代器结果收集到一个向量中。最终，该向量将包含原始向量中每个增加了1的项。

```rust
    let v1: Vec<i32> = vec![1, 2, 3];

    let v2: Vec<_> = v1.iter().map(|x| x + 1).collect();

    assert_eq!(v2, vec![2, 3, 4]);
```

##### 调用 map 方法以创建一个新迭代器，然后调用 collect 方法来消费新迭代器并创建一个向量

因为 `map` 接收一个闭包，我们可以指定我们希望对每个项执行的任何操作。这是一个很好的例子，说明了闭包如何让您定制某些行为，同时重用 `Iterator` 特性提供的迭代行为。
