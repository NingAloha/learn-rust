## 使用线程同时运行代码

在大多数现代操作系统中，程序的代码在一个_进程_中运行，操作系统同时管理多个进程。在你的程序中，也可以有独立的部分同时运行。运行这些独立部分的功能称为_线程_。

将程序中的计算拆分为多线程可以提高性能，因为程序可以同时执行多个任务，但这也增加了复杂性。由于线程可以同时运行，不保证不同线程上的代码部分按照顺序运行。这可能导致问题，例如：

*   竞争条件：线程对数据或资源的访问次序不一致
*   死锁：两个线程相互等待对方释放资源，从而阻止两个线程继续运行
*   仅在某些情况下发生、难以重现和修复的错误

Rust尝试减轻使用线程的负面影响，但在多线程环境中编程依然需要仔细考虑，并要求与单线程程序不同的代码结构。

编程语言以多种方式实现线程。许多操作系统提供用于创建新线程的API。这种语言调用操作系统API创建线程的模型有时被称为_1:1_，意味着每一个语言线程对应一个操作系统线程。

许多编程语言提供它们自己的特殊线程实现。由编程语言提供的线程被称为_绿_线程，使用这些绿线程的语言将在不同数量的操作系统线程上下文中执行它们。因此，绿线程模型被称为_M:N_模型：每`N`个操作系统线程对应`M`个绿线程，其中`M`和`N`不一定相同。

每种模型都有其优劣势，对Rust来说，最重要的权衡是运行时支持。_运行时_是一个模糊的术语，在不同的环境中意义不同。

在这个上下文中，_运行时_是指每个二进制文件中由语言包含的代码。这些代码可能很大或很小，视语言而定，但每个非汇编语言都会有一些运行时代码。因此，通常当人们说一种语言“没有运行时”时，他们常指“运行时很小”。较小的运行时功能较少，但其优点是生成较小的二进制文件，这使得在更多的环境中更容易将语言与其他语言结合。尽管许多语言愿意为了更多功能增加运行时大小，Rust需要几乎没有运行时，并且无法在调用C以保持性能方面妥协。

绿线程M:N模型需要更大的语言运行时来管理线程。因此，Rust标准库只提供1:1线程实现。由于Rust是一个如此低级的语言，如果更喜欢以一些如控制线程运行时和降低上下文切换成本等方面的开销为代价，还有实现M:N线程的第三方库。
