### RefCell<T>/Rc<T> 和 Mutex<T>/Arc<T> 之间的相似性

您可能已经注意到，`counter` 是不可变的，但我们可以获取对其中值的可变引用；这意味着 `Mutex<T>` 提供了内部可变性，就像 `Cell` 家族一样。在第15章中，我们使用 `RefCell<T>` 使我们可以修改 `Rc<T>` 中的内容，同样地，我们使用 `Mutex<T>` 来修改 `Arc<T>` 中的内容。

另一个需要注意的细节是，当您使用 `Mutex<T>` 时，Rust 不能保护您免受所有类型的逻辑错误。回想一下第15章中，使用 `Rc<T>` 存在创建引用循环的风险，即两个 `Rc<T>` 值互相引用，导致内存泄漏。同样地，`Mutex<T>` 存在创建 _死锁_ 的风险。这种情况发生在一个操作需要锁定两个资源，并且两个线程各自获得了一个锁，导致它们无限期地相互等待。如果您对死锁感兴趣，可以尝试创建一个包含死锁的 Rust 程序；然后研究任何语言中的互斥锁死锁缓解策略，并尝试在 Rust 中实现它们。标准库中关于 `Mutex<T>` 和 `MutexGuard` 的 API 文档提供了有用的信息。

您还可以阅读 [书中关于 `Send` 和 `Sync` 特性的章节](https://doc.rust-lang.org/stable/book/ch16-04-extensible-concurrency-sync-and-send.html)，看看我们如何将它们与自定义类型一起使用。
