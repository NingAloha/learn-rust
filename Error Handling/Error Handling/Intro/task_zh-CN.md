## 错误处理

Rust 对可靠性的承诺体现在其错误处理机制上。错误是软件中的常见现象，因此 Rust 提供了多种功能来处理问题出现的情况。在许多情况下，Rust 要求您承认错误的可能性并采取某些行动，才能使代码编译成功。此要求通过确保您在将代码部署到生产环境之前发现并妥善处理错误，从而使程序更稳健。

Rust 将错误分为两大类：可恢复错误和不可恢复错误。对于可恢复错误，比如文件未找到错误，合理的做法是将问题报告给用户并重试操作。不可恢复错误通常是程序错误的征兆，比如试图访问数组末尾以外的位置。

大多数语言不区分这两类错误，通常使用异常等机制统一处理这两类错误。Rust 没有异常机制。相反，Rust 通过 `Result<T, E>` 类型处理可恢复错误，使用 `panic!` 宏在程序遇到不可恢复错误时停止执行。本章首先介绍调用 `panic!`，然后讨论返回 `Result<T, E>` 值。此外，我们还将探讨在决定是恢复错误还是终止程序执行时的考虑因素。
