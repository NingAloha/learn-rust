### 传播错误

当您编写调用可能会失败的函数时，与其在此函数内部处理错误，不如将错误返回给调用代码，以便调用代码可以决定该如何做。这被称为_传播_错误，给予调用代码更多的控制，因为在调用代码中，可能会有更多的信息或逻辑来决定如何处理错误，而在您的代码上下文中可能没有。

例如，下面的代码段展示了一个从文件中读取用户名的函数。如果文件不存在或无法读取，该函数将把这些错误返回给调用此函数的代码。

```rust
    use std::io;
    use std::io::Read;
    use std::fs::File;

    fn read_username_from_file() -> Result<String, io::Error> {
        let f = File::open("hello.txt");

        let mut f = match f {
            Ok(file) => file,
            Err(e) => return Err(e),
        };

        let mut s = String::new();

        match f.read_to_string(&mut s) {
            Ok(_) => Ok(s),
            Err(e) => Err(e),
        }
    }
```

##### 使用`match`将错误返回给调用代码的函数

这个函数可以用更简短的方式编写，但我们将从手动处理的方式开始，以便探讨错误处理方法；最终，我们将展示更简短的方法。首先让我们来看函数的返回类型：`Result<String, io::Error>`。这意味着函数返回的是类型`Result<T, E>`的值，其中泛型参数`T`用具体类型`String`填充，而泛型参数`E`用具体类型`io::Error`填充。如果此函数成功执行，调用此函数的代码将接收到一个包含用户名的`Ok`值——这是从文件中读取的。如果此函数遇到任何问题，调用此函数的代码将接收到一个包含`io::Error`实例的`Err`值，其中包含有关问题的更多信息。我们选择`io::Error`作为此函数的返回类型，因为这是我们调用的函数体中可能失败的两个操作返回的错误值的类型：`File::open`函数和`read_to_string`方法。

函数体从调用`File::open`函数开始。然后，我们使用一个类似于“使用`match`表达式处理可能返回的Result变体”的`match`来处理返回的`Result`值，但不同的是，我们在`Err`情况下没有调用`panic!`，而是提前从此函数返回，并将`File::open`的错误值作为此函数的错误值传递回调用代码。如果`File::open`成功，我们将文件句柄存储在变量`f`中并继续。

然后我们在变量`s`中创建一个新的`String`，并在文件句柄`f`上调用`read_to_string`方法，将文件内容读取到`s`中。`read_to_string`方法也会返回一个`Result`，因为它可能会失败，即使`File::open`成功了。因此，我们需要另一个`match`来处理那个`Result`：如果`read_to_string`成功，那么函数也就成功了，我们返回文件中用户名的`s`，并用`Ok`包装。如果`read_to_string`失败，我们以与处理`File::open`返回值的`match`相同的方式返回错误值。不过，我们不需要显式地说`return`，因为这是函数的最后一个表达式。

调用这段代码的代码将处理获得的`Ok`值（包括用户名）或`Err`值（包括`io::Error`）。我们不知道调用代码会如何处理这些值。如果调用代码得到一个`Err`值，它可以调用`panic!`并使程序崩溃，使用一个默认的用户名，或者从除文件之外的地方查找用户名。例如，我们没有足够的信息知道调用代码实际在做什么，因此我们将所有的成功或错误信息向上传播以供它适当地处理。

这种传播错误的模式在Rust中非常普遍，以至于Rust提供了问号运算符`?`来简化这一过程。
