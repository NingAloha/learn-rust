## 定义模块以控制作用域和隐私

_模块_ 让我们可以将代码库中的代码组织成易于阅读和重用的组。模块还控制项目的_隐私_，即项目是否可以被外部代码使用（_公共_）或是内部实现细节，外部不可用（_私有_）。

例如，让我们编写一个库代码库，提供餐馆的功能。我们将定义函数的签名，但不填写函数体，以集中精力在代码的组织，而不是在代码中真正实现一个餐馆。

在餐饮业中，餐馆的某些部分被称为 _前厅_，而另一些则称为 _后厨_。前厅是顾客所在的地方，这里有接待员为顾客安排座位，服务员接待订单和收款，调酒师调制饮品。后厨是厨师和厨工在厨房工作的地方，洗碗工清洗餐具，经理进行行政工作。

为了以与真实餐馆相同的方式结构化我们的代码库，我们可以将函数组织成嵌套模块。通过运行 `cargo new --lib restaurant` 创建一个名为 `restaurant` 的新库；然后将下面示例中的代码放入 _src/lib.rs_ 以定义一些模块和函数签名。

```rust
    mod front_of_house {
        mod hosting {
            fn add_to_waitlist() {}

            fn seat_at_table() {}
        }

        mod serving {
            fn take_order() {}

            fn serve_order() {}

            fn take_payment() {}
        }
    }
```

##### 一个包含其他模块的 front_of_house 模块，然后包含函数

我们通过 `mod` 关键字来定义一个模块，然后指定模块的名称（在这个例子中是 `front_of_house`），并在模块体周围加上花括号。在模块内部，我们可以有其他模块，如本例中的 `hosting` 和 `serving` 模块。模块还可以包含其他项目的定义，如结构体、枚举、常量、特性，或如代码片段中的函数。

通过使用模块，我们可以将相关的定义分组并命名它们之间的关系。使用此代码的程序员能够更容易地找到他们想要使用的定义，因为他们可以根据组导航代码，而不必阅读所有定义。在此代码中添加新功能的程序员会知道在哪里放置代码以保持程序的组织性。

之前我们提到过 _src/main.rs_ 和 _src/lib.rs_ 被称为 _代码库根_。它们的名字来源于它们两者中的任何一个文件的内容构成根代码库模块结构的模块，称为_模块树_。

下面是上面代码片段中的结构的模块树。

```text
crate
 └── front_of_house
     ├── hosting
     │   ├── add_to_waitlist
     │   └── seat_at_table
     └── serving
         ├── take_order
         ├── serve_order
         └── take_payment
```

##### 模块树

此树显示了一些模块如何嵌套在彼此之中（例如，`hosting` 嵌套在 `front_of_house` 中）。树还显示了一些模块是彼此的 _兄弟_，这意味着它们在同一个模块中定义（`hosting` 和 `serving` 在 `front_of_house` 中定义）。继续这个家庭比喻，如果模块 A 包含在模块 B 内，我们说模块 A 是模块 B 的_子_，而模块 B 是模块 A 的_父_。注意，整个模块树都根植于名为 `crate` 的隐式模块下。

模块树可能会让你想起你计算机上的文件系统目录树；这是一个非常恰当的比较！就像文件系统中的目录一样，你使用模块来组织你的代码。就像目录中的文件一样，我们需要一种方法来找到我们的模块。
