### 用生命周期防止悬空引用

生命周期的主要目标是防止悬空引用，悬空引用会导致程序引用非预期的数据。请看下面的程序，它包含一个外层作用域和一个内层作用域。

```rust,ignore,does_not_compile
    {
        let r;

        {
            let x = 5;
            r = &x;
        }

        println!("r: {}", r);
    }
```

#### 尝试使用值已超出作用域的引用

> 注意：此例中及接下来几个实例中的变量在声明时未被赋值，因此变量名存在于外层作用域。乍一看，这可能与 Rust 的无 null 值特性相矛盾。然而，如果我们在为变量赋值之前尝试使用它，会得到一个编译时错误，这表明 Rust 确实不允许使用 null 值。

外层作用域声明了一个名为 `r` 的变量，初始时没有赋值，内层作用域声明了一个名为 `x` 的变量，初始值为 5。在内层作用域中，我们尝试将 `r` 设为对 `x` 的引用。然后内层作用域结束，我们尝试打印 `r` 中的值。此代码将无法编译，因为 `r` 所引用的值在我们尝试使用它之前已经超出作用域。错误信息如下：

```console
error[E0597]: `x` does not live long enough
  --> src/main.rs:7:17
   |
7  |             r = &x;
   |                 ^^ borrowed value does not live long enough
8  |         }
   |         - `x` dropped here while still borrowed
9  | 
10 |         println!("r: {}", r);
   |                           - borrow later used here
```

变量 `x` 的“生命周期不够长”。原因是，当内层作用域在第 7 行结束时，`x` 将超出作用域。但 `r` 对外层作用域仍然是有效的；由于其作用域更大，我们说它的“生命更长”。如果 Rust 允许这段代码工作，`r` 将会引用在 `x` 超出作用域时已释放的内存，并且任何针对 `r` 的操作都无法正确工作。那么 Rust 是如何判断这段代码无效的呢？它使用了借用检查器。
