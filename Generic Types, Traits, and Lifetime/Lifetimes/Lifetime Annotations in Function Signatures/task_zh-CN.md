### 函数签名中的生命周期注解

现在让我们在`longest`函数的上下文中检查生命周期注解。与泛型类型参数一样，我们需要在函数名和参数列表之间的尖括号中声明泛型生命周期参数。我们想在这个签名中表达的约束是参数和返回值中的所有引用必须具有相同的生命周期。我们将这个生命周期命名为`'a`，然后将其添加到每个引用中，如下面的代码片段所示。

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

#### `longest`函数定义指定签名中的所有引用必须有相同的生命周期`'a`

当我们将这个代码与调用`longest`函数来找到两个字符串片段中较长的那个的`main`函数一起使用时，这段代码应该可以编译并产生我们期望的结果。

现在的函数签名告诉Rust对某个生命周期`'a`，函数接受两个参数，它们都是至少和生命周期`'a`一样长的字符串片段。函数签名还告诉Rust从函数返回的字符串片段至少与生命周期`'a`一样长。实际上，这意味着`longest`函数返回的引用的生命周期与传入的引用中的较小生命周期相同。这些约束正是我们希望Rust强制执行的。请记住，当我们在这个函数签名中指定生命周期参数时，我们并没有改变传入值或返回值的生命周期。相反，我们是在指示借用检查器应拒绝不符合这些约束的任何值。注意，`longest`函数不需要确切知道`x`和`y`将存在多久，只需要有某个作用域能替代`'a`以满足这个签名。

在函数中标注生命周期时，注解放在函数签名中，而不是函数体中。Rust可以在没有帮助的情况下分析函数内部的代码。然而，当一个函数有来自或到该函数外部代码的引用时，Rust几乎无法自行判断参数或返回值的生命周期。每次调用函数时，生命周期可能会不同。这就是为什么我们需要手动注解生命周期。

当我们将具体的引用传递给`longest`函数时，被替换为`'a`的具体生命周期是`x`和`y`作用域重叠的部分。换句话说，泛型生命周期`'a`将获得等于`x`和`y`的生命周期中较小的那个的具体生命周期。因为我们用相同的生命周期参数`'a`标注了返回的引用，因此返回的引用将在`x`和`y`的较小生命周期内同样有效。

让我们通过传递不同具体生命周期的引用来查看生命周期注解如何限制`longest`函数。下面的代码是一个简单的例子。

```rust
fn main() {
    let string1 = String::from("long string is long");

    {
        let string2 = String::from("xyz");
        let result = longest(string1.as_str(), string2.as_str());
        println!("The longest string is {}", result);
    }
}
```

#### 使用`longest`函数与具有不同具体生命周期的`String`值的引用

在这个例子中，`string1`在外部作用域结束之前是有效的，`string2`在内部作用域结束之前是有效的，而`result`引用的是在内部作用域结束之前有效的东西。运行这段代码，你会看到借用检查器批准了这段代码；它可以编译并输出`The longest string is long string is long`。
