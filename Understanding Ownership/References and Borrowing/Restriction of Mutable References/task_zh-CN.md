## 可变引用的限制

但是可变引用有一个重要限制：在特定作用域中，你只能有一个特定数据的可变引用。以下代码将失败：

```rust
    let mut s = String::from("hello");

    let r1 = &mut s;
    let r2 = &mut s;

    println!("{}, {}", r1, r2);
```

这里是错误信息：

```text
    error[E0499]: cannot borrow `s` as mutable more than once at a time
     --> src/main.rs:5:14
      |
    4 |     let r1 = &mut s;
      |              ------ 首次可变借用发生在这里
    5 |     let r2 = &mut s;
      |              ^^^^^^ 第二次可变借用发生在这里
    6 |
    7 |     println!("{}, {}", r1, r2);
      |                        -- 首次借用在此被使用
```

这个限制允许变异，但方式非常受控。这是新 Rust 用户常常挣扎的地方，因为大多数编程语言都是允许你随时变异。

这种限制的好处在于 Rust 能在编译时防止数据竞争。_数据竞争_ 类似于竞争条件，发生在以下三种行为同时出现时：

*   两个或多个指针在同一时间访问相同数据。
*   至少有一个指针用于写入数据。
*   没有用于同步数据访问的机制。

数据竞争会导致未定义行为，当你在运行时试图追踪问题来源时，这种问题可能很难诊断和修复；Rust 通过不编译含有数据竞争的代码来防止这个问题的发生！

和往常一样，我们可以使用大括号来创建新的作用域，允许有多个可变引用，只是不能同时存在：

```rust
    let mut s = String::from("hello");

    {
        let r1 = &mut s;

    } // r1 在这里超出作用域，因此我们可以创建一个新的引用没有问题。

    let r2 = &mut s;
```

合并可变引用和不可变引用也存在类似的规则。此代码导致错误：

```rust
    let mut s = String::from("hello");

    let r1 = &s; // 没问题
    let r2 = &s; // 没问题
    let r3 = &mut s; // 大问题

    println!("{}, {}, and {}", r1, r2, r3);
```

这里是错误信息：

```text
    error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
     --> src/main.rs:6:14
      |
    4 |     let r1 = &s; // 没问题
      |              -- 不可变借用发生在这里
    5 |     let r2 = &s; // 没问题
    6 |     let r3 = &mut s; // 大问题
      |              ^^^^^^ 可变借用发生在这里
    7 |
    8 |     println!("{}, {}, and {}", r1, r2, r3);
      |                                -- 不可变借用在此被使用
```

吁！我们 _也_ 不能在拥有不可变引用的同时拥有可变引用。不可变引用的用户不希望值会突然被改变！然而，多个不可变引用是可以的，因为没有只是读取数据的人有能力影响其他人的数据读取。
