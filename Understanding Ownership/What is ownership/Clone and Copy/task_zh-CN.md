## 变量与数据交互方式：Clone

如果我们确实想深度复制 `String` 的堆数据，而不仅仅是栈数据，可以使用一个常用的方法叫做 `clone`。我们将在“结构体”这一章讨论方法语法，但因为方法是许多编程语言的通用特性，你可能已经见过它们。

下面是 `clone` 方法的一个例子：

```rust
let s1 = String::from("hello");
let s2 = s1.clone();

println!("s1 = {}, s2 = {}", s1, s2);
```

这能够正常工作，并显式地产生图3中展示的行为，其中堆数据真的被复制了。

当你看到调用 `clone` 时，你知道一些任意代码正在执行，而这些代码可能开销很大。这是一个视觉指示，说明有不同的事情在发生。

## 仅栈数据：Copy

还有另一个问题我们还没有谈到。这段使用整数的代码，其中一部分已在“将变量x的整数值赋值给y”代码片段中展示，工作正常且是有效的：

```rust
let x = 5;
let y = x;

println!("x = {}, y = {}", x, y);
```

但这段代码似乎与我们刚刚学到的相矛盾：我们没有调用 `clone`，但 `x` 仍然有效而没有被移动到 `y`。

原因是像整数这样的类型在编译时具有已知的大小，完全存储在栈上，因此实际值的复制速度很快。这意味着在创建变量 `y` 后，我们没有理由阻止 `x` 变得有效。换句话说，这里深复制和浅复制没有区别，因此调用 `clone` 不会与通常的浅复制有任何不同，我们可以省略它。

Rust 有一个特殊的注释叫做 `Copy` trait，我们可以将其放在像整数这样存储在栈上的类型上（我们将在第10章详细讨论 trait）。如果一个类型实现了 `Copy` trait，较老的变量在赋值后仍然可用。如果一个类型或它的任何部分实现了 `Drop` trait，Rust 不允许我们用 `Copy` trait 注释一个类型。如果当值超出作用域时需要发生特殊处理，而我们将 `Copy` 注释添加到该类型，就会得到编译时错误。要了解如何将 `Copy` 注释添加到你的类型以实现 trait，请参见附录C中的[“可派生的 trait”](https://doc.rust-lang.org/stable/book/appendix-03-derivable-traits.html)。

那么哪些类型实现了 `Copy` trait 呢？你可以检查给定类型的文档以确认，但一般来说，任何简单标量值的集合都可以实现 `Copy`，而任何需要分配或某种形式的资源的东西都不能实现 `Copy`。以下是实现 `Copy` 的一些类型：

*   所有整数类型，例如 `u32`。
*   布尔类型，`bool`，具有值 `true` 和 `false`。
*   所有浮点类型，例如 `f64`。
*   字符类型，`char`。
*   元组，如果它们仅包含也实现 `Copy` 的类型。例如，`(i32, i32)` 实现 `Copy`，但 `(i32, String)` 不会。
