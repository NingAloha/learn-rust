## 字符串类型

为了阐明所有权的规则，我们需要一种比“常见编程概念”章节中的[“数据类型”](https://doc.rust-lang.org/stable/book/ch03-02-data-types.html#data-types)部分涵盖的类型更复杂的数据类型。之前涵盖的类型都是存储在栈上，当其作用域结束时会被弹出，但我们想要观察存储在堆上的数据，并探讨Rust如何判断何时清理这些数据。

我们将在这里使用`String`作为例子，并专注于与所有权相关的部分。这些方面也适用于其他复杂数据类型，无论它们是由标准库提供的还是由您创建的。我们将在“常见集合”章节中更深入地讨论`String`。

我们已经见过字符串字面量，它是在程序中硬编码的字符串值。字符串字面量很方便，但并不适合我们可能想要使用文本的所有情况。原因之一是它们是不可变的。另一个原因是，当我们编写代码时，并不是每个字符串值都是已知的：例如，如果我们想获取用户输入并存储它怎么办？对于这些情况，Rust有第二种字符串类型，即`String`。这种类型是在堆上分配的，因此能够存储在编译时未知的文本数量。您可以使用`from`函数从字符串字面量创建一个`String`，如下所示：

```rust
let s = String::from("hello");
```

双冒号（`::`）是一种操作符，允许我们将这个特定的`from`函数置于`String`类型的命名空间下，而不是使用类似`string_from`的名称。我们将在第五章的[“方法语法”](https://doc.rust-lang.org/stable/book/ch05-03-method-syntax.html#method-syntax)部分，以及在第七章中有关模块命名空间的[“路径用于引用模块树中的项”](https://doc.rust-lang.org/stable/book/ch07-03-paths-for-referring-to-an-item-in-the-module-tree.html)时讨论这种语法。

这种类型的字符串_可以_被修改：

```rust
let mut s = String::from("hello");

s.push_str(", world!"); // push_str()将字面量追加到String中

println!("{}", s); // 这将打印`hello, world!`
```

那么，这里有什么不同呢？为什么`String`可以被修改，而字面量不能？区别在于这两种类型如何处理内存。

### 内存与分配

在字符串字面量的情况下，我们在编译时就知道其内容，因此文本被直接硬编码到最终的可执行文件中。这就是字符串字面量快速且高效的原因。但这些属性仅源于字符串字面量的不可变性。不幸的是，我们不能为每个在编译时大小未知且在程序运行时可能会改变的文本片段在二进制文件中放置一块内存。

使用`String`类型，为了支持可变且可增长的文本块，我们需要在堆上分配一块编译时未知的内存，以容纳内容。这意味着：

* 需要在运行时从内存分配器请求内存。
* 当我们不再使用`String`时，需要一种方法将这块内存归还给分配器。

第一部分是由我们来完成的：当我们调用`String::from`时，其实现会请求所需的内存。这在编程语言中几乎是通用的。

然而，第二部分则有所不同。在有_垃圾回收器（GC）_的语言中，GC会跟踪并清理不再使用的内存，并且我们不需要考虑它。没有GC的情况下，我们则需要负责识别不再使用的内存并调用代码显式返回它，就像我们请求它时一样。正确处理这件事在历史上一直是一个困难的编程问题。如果我们忘记了，会浪费内存。如果太早进行，我们会得到无效的变量。如果做两次，这也是一个错误。我们需要将每次`分配`与每次`释放`精确配对。

Rust选择了一条不同的路径：一旦变量超出作用域，内存将自动归还。这是从代码片段中用`String`而不是字符串字面量的作用域示例的一个版本：

```rust
{
let s = String::from("hello"); // 从这点开始，s有效

// 使用s做一些事情
}                                  // 这个作用域现在结束，s不再有效
```

当`s`超出作用域时，有一个自然的点可以将`String`所需的内存归还给分配器。当一个变量超出作用域时，Rust为我们调用一个特殊函数。这种函数称为`drop`，它是`String`的作者可以放置内存归还代码的地方。Rust会在闭合的大括号时自动调用`drop`。

> 注意：在C++中，资源在其生命周期结束时被释放的这种模式有时被称为资源获取即初始化（RAII）。如果您使用过RAII模式，Rust中的`drop`函数会让您感到熟悉。

这种模式对Rust代码的编写方式有着深远影响。现在看起来可能很简单，但在更复杂的情况下，当我们希望多个变量使用在堆上分配的数据时，代码的行为可能会出乎意料。现在让我们探讨其中的一些情况。
