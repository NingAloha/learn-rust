### 使用 `macro_rules!` 的声明性宏用于通用元编程

在 Rust 中，使用最广泛的宏形式是_声明性宏_。这些有时也被称为“示例宏”、“`macro_rules!` 宏”或简称“宏”。声明性宏的核心是允许你编写与 Rust 的 `match` 表达式类似的东西。如第 6 章所讨论的，`match` 表达式是一种控制结构，它接收一个表达式，对该表达式的结果值进行模式匹配，然后运行与匹配模式相关联的代码。宏也会将一个值与特定代码关联的模式进行比较：在这种情况下，值是传递给宏的字面 Rust 源代码；模式与该源代码的结构进行比较；当模式匹配时，与该模式相关联的代码将替换传递给宏的代码。这一切都发生在编译期间。

要定义一个宏，你使用 `macro_rules!` 结构。让我们通过查看 `vec!` 宏的定义来探索如何使用 `macro_rules!`。第 8 章讨论了如何使用 `vec!` 宏创建具有特定值的新向量。例如，以下宏创建了一个包含三个整数的新向量：

```rust
    let v: Vec<u32> = vec![1, 2, 3];
```

我们也可以使用 `vec!` 宏来创建一个包含两个整数的向量或五个字符串切片的向量。我们无法用函数做到这一点，因为我们不能预先知道值的数量或类型。

下面的代码片段显示了一个稍加简化的 `vec!` 宏定义。

```rust
    #[macro_export]
    macro_rules! vec {
        ( $( $x:expr ),* ) => {
            {
                let mut temp_vec = Vec::new();
                $(
                    temp_vec.push($x);
                )*
                temp_vec
            }
        };
    }
```

##### 简化版的 vec! 宏定义

> 注意：标准库中 `vec!` 宏的实际定义包括预先分配适当内存的代码。那段代码是一种优化，为简化示例我们在此未包含。

`#[macro_export]` 注解表明只要定义宏的 crate 被导入到作用域内，这个宏就应该可用。没有这个注解，宏无法被带入作用域。

然后我们用 `macro_rules!` 开始宏定义，并在定义的宏名称后_不加_感叹号。在本例中，名称 `vec` 后跟大括号，表示宏定义的主体。

`vec!` 主体中的结构类似于 `match` 表达式的结构。这里我们有一行模式 `( $( $x:expr ),* )`，随之是 `=>` 和与该模式相关联的代码块。如果模式匹配，相关的代码块将被发出。鉴于这是该宏中唯一的模式，因此只有一种有效的匹配方式；任何其他模式都会导致错误。更复杂的宏将有多于一行。

宏定义中的有效模式语法与第 18 章中介绍的模式语法不同，因为宏模式是与 Rust 代码结构而非值进行匹配的。让我们解释一下上面代码片段中模式的各个部分；完整的宏模式语法，请参见[参考](https://doc.rust-lang.org/1.30.0/book/first-edition/macros.html)。

首先，一对括号包含整个模式。接下来是一个美元符号`$`，后随一对括号，用于捕获与括号内模式匹配的值，然后在替换代码中使用。在 `$()` 中是 `$x:expr`，匹配任何 Rust 表达式并将表达式命名为 `$x`。

紧随 `$()` 后面的逗号表示在与 `$()` 中代码匹配的代码之后可以出现一个可选的字面逗号分隔符字符。`*` 指定了模式匹配零个或多个在 `*` 之前的内容。

当我们用 `vec![1, 2, 3];` 调用这个宏时，`$x` 模式会与三个表达式 `1`、`2` 和 `3` 匹配三次。

现在让我们看看与该模式中的代码主体相关联的模式：`temp_vec.push()` 在 `$()*` 中根据模式匹配的次数为 `$()` 的每个部分生成代码。`$x` 被替换为每个匹配的表达式。当我们用 `vec![1, 2, 3]` 调用这个宏时，生成替换这个宏调用的代码将是如下：

```rust
    let mut temp_vec = Vec::new();
    temp_vec.push(1);
    temp_vec.push(2);
    temp_vec.push(3);
    temp_vec
```

我们已经定义了一个可以接受任意数量任意类型参数的宏，并能生成代码来创建包含指定元素的向量。

`macro_rules!` 存在一些奇怪的边界情况。未来，Rust 将有第二种声明性宏，它会以类似的方式工作，但能修复这些边界情况。在那次更新之后，`macro_rules!` 将基本上被弃用。考虑到这一点，以及大多数 Rust 程序员会_使用_而不是_编写_宏，我们不会进一步讨论 `macro_rules!`。要了解更多关于如何编写宏的信息，请查阅在线文档或其他资源，例如[《Rust 小书·宏》](https://danielkeep.github.io/tlborm/book/index.html)。
