### 从属性生成代码的过程宏

第二种形式的宏是_过程宏_，其行为更像函数（并且是一种过程）。过程宏接受一些代码作为输入，操作该代码，并生成一些代码作为输出，而不是像声明宏那样匹配模式并用其他代码替换代码。

三种类型的过程宏（自定义派生、类似属性和类似函数）都以类似的方式工作。

在创建过程宏时，定义必须存在于其自己的包中，且具有特殊的包类型。这是由于复杂的技术原因，我们希望未来能消除这些限制。使用过程宏的代码如下例所示，其中 `some_attribute` 是用于特定宏的占位符。

```rust
    use proc_macro;

    #[some_attribute]
    pub fn some_name(input: TokenStream) -> TokenStream {
    }
```

##### 使用过程宏的示例

定义过程宏的函数接受一个 `TokenStream` 作为输入，并生成一个 `TokenStream` 作为输出。`TokenStream` 类型由 Rust 附带的 `proc_macro` 包定义，表示一系列的标记。这是宏的核心：宏操作的源代码构成输入的 `TokenStream`，宏生成的代码是输出的 `TokenStream`。该函数还附加了一个属性，指定我们正在创建哪种类型的过程宏。我们可以在同一个包中包含多种类型的过程宏。
