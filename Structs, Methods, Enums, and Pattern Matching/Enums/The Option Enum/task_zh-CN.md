### `Option` 枚举及其优于空值的优点

在上一节中，我们探讨了 `IpAddr` 枚举如何让我们利用 Rust 的类型系统将更多信息编码到程序中，而不仅仅是数据。本节将研究 `Option` 的案例，`Option` 是标准库中定义的另一个枚举。`Option` 类型在许多地方被使用，因为它编码了一个非常常见的场景：一个值要么存在，要么不存在。用类型系统表达这个概念意味着编译器可以检查您是否处理了所有应该处理的情况；此功能可以防止在其他编程语言中非常常见的错误。

编程语言设计通常被认为是包含哪些特性，但排除哪些特性也很重要。Rust 没有很多其他语言具有的空值特性。*空值* 是一个表示无值的值。在具有空值的语言中，变量始终可以处于两种状态之一：空或非空。

在 2009 年的演讲“空引用：十亿美元的错误”中，空值的发明者托尼·霍尔说：

> 我称之为我的十亿美元错误。当时，我正在设计第一个面向对象语言的全面类型系统。我的目标是确保所有引用的使用绝对安全，由编译器自动进行检查。但我忍不住诱惑加入了一个空引用，仅仅因为实现起来非常简单。这导致了无数的错误、漏洞和系统崩溃，可能在过去的四十年里造成了数十亿美元的痛苦和损失。

空值的问题在于，如果您试图将一个空值当作非空值使用，就会遇到某种错误。因为这种空或非空特性普遍存在，非常容易犯这种错误。

然而，空值尝试表达的概念仍然是一个有用的概念：空值是当前无效或由于某种原因缺失的值。

问题实际上不在于概念，而在于特定的实现。因此，Rust 没有空值，但它有一个枚举可以编码值存在或缺失的概念。这个枚举是 `Option<T>`，它在标准库中定义如下： 

```rust
enum Option<T> {
    Some(T),
    None,
}
```

`Option<T>` 枚举非常有用，它甚至包括在预引导中；您不需要显式引入它。此外，它的变体也是如此：您可以直接使用 `Some` 和 `None`，无需 `Option::` 前缀。`Option<T>` 枚举仍然只是一个普通的枚举，`Some(T)` 和 `None` 仍然是 `Option<T>` 类型的变体。

`<T>` 语法是 Rust 的功能之一，我们尚未讨论。它是一个泛型类型参数，我们将在“泛型类型、特性和生命周期”章节中更详细地讨论泛型。目前，您只需知道 `<T>` 意味着 `Option` 枚举的 `Some` 变体可以容纳任意类型的一块数据。以下是一些使用 `Option` 值存储数字类型和字符串类型的示例：

```rust
let some_number = Some(5);
let some_string = Some("a string");

let absent_number: Option<i32> = None;
```

如果我们使用 `None` 而不是 `Some`，我们需要告诉 Rust 我们有哪些类型的 `Option<T>`，因为编译器无法通过仅查看 `None` 值来推断 `Some` 变体将持有的类型。

当我们有一个 `Some` 值时，我们知道该值存在且被 `Some` 持有。当我们有一个 `None` 值时，在某种意义上，它与空值的含义相同：我们没有一个有效的值。那么，为什么 `Option<T>` 比空值更好呢？

简而言之，因为 `Option<T>` 和 `T` （其中 `T` 可以是任何类型）是不同的类型，编译器不会让我们把 `Option<T>` 值当作绝对有效的值使用。例如，这段代码将无法编译，因为它尝试将一个 `i8` 与一个 `Option<i8>` 相加：

```rust,ignore,does_not_compile
let x: i8 = 5;
let y: Option<i8> = Some(5);

let sum = x + y;
```

如果我们运行这段代码，会收到类似这样的错误信息：

```console
error[E0277]: cannot add `Option<i8>` to `i8`
 --> src/main.rs:5:17
  |
5 |     let sum = x + y;
  |                 ^ no implementation for `i8 + Option<i8>`
  |
  = help: the trait `Add<Option<i8>>` is not implemented for `i8`
  ```

这种情况真让人振奋！实际上，这条错误信息意味着 Rust 不知道如何将 `i8` 和 `Option<i8>` 相加，因为它们是不同类型。当我们在 Rust 中有一个类似 `i8` 的类型值时，编译器将确保我们始终拥有一个有效的值。我们可以不必在使用此值之前检查空值，从而更自信地进行处理。只有当我们有一个 `Option<i8>` （或我们正在处理的任何类型）时，我们才需要担心可能没有值，并且编译器会确保我们在使用该值之前处理了这种情况。

换言之，在您可以用 `T` 执行操作之前，您必须将 `Option<T>` 转换为 `T`。这通常有助于捕获空值常见问题之一：假设某事物不是空值，而事实却是。

不必担心错误地假设非空值有助于提高对代码的信心。为了拥有一个可能为空值的值，您必须显式选择通过使该值类型为 `Option<T>` 来实现。当您使用该值时，您需要显式处理值为空的情况。在值类型不是 `Option<T>` 的地方，您可以安全假设值不是空值。这是 Rust 的一个有意设计决策，以限制空值的普遍性并提高 Rust 代码的安全性。

那么，当您有一个 `Option<T>` 类型的值时，如何从 `Some` 变体中获取 `T` 值以便使用该值呢？`Option<T>` 枚举在各种情况下都有大量有用的方法；您可以在[其文档][docs]<!-- ignore -->中查看。熟悉 `Option<T>` 上的方法在您的 Rust 学习之旅中将非常有用。

通常，为了使用 `Option<T>` 值，您希望编写代码来处理每个变体。您需要一些代码仅在您有一个 `Some(T)` 值时运行，并且此代码可以使用内部的 `T`。若有一个 `None` 值，您希望其他代码运行，而该代码没有可用的 `T` 值。`match` 表达式是一个控制流构造，当与枚举一起使用时，正是这样：它会根据其拥有的枚举的哪个变体运行不同的代码，并且可以使用匹配值内部的数据。
