### 全匹配模式与`_`占位符

使用枚举，我们可以针对一些特定的值采取特殊操作，但对于所有其他值采取默认操作。想象一下，我们在实现一个游戏，如果你在骰子中掷出3，你的玩家不会移动，而是获得一顶新的花哨帽子。如果你掷出7，你的玩家则失去一顶花哨帽子。对于其他所有值，你的玩家在棋盘上移动相应的步数。以下是一个`match`语句实现了这一逻辑，其中骰子结果被硬编码为一个值而非随机值，并且其他所有逻辑由没有主体的函数表示，因为实际实现它们超出了这个例子的范围：

```rust
let dice_roll = 9;
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    other => move_player(other),
}

fn add_fancy_hat() {}
fn remove_fancy_hat() {}
fn move_player(num_spaces: u8) {}
```

对于前两个分支，模式是字面值3和7。对于覆盖其他所有可能值的最后一个分支，模式是我们选择命名为`other`的变量。运行该分支的代码通过将变量传递给`move_player`函数使用了它。

即使我们没有列出u8所有可能的值，这段代码仍可编译，因为最后一个模式将匹配所有未具体列出的值。这种全匹配模式满足了`match`必须是穷尽的要求。注意，我们必须把全匹配分支放在最后，因为模式是按顺序计算的。如果我们在全匹配之后添加分支，Rust会警告我们，因为那些后来的分支永远不会匹配！

Rust还有一种模式可以在我们不希望使用全匹配模式中的值时使用：`_`，这是一种特殊模式，可以匹配任何值并且不绑定至该值。这告诉Rust我们不会使用该值，因此Rust不会警告我们有未使用的变量。

让我们改变游戏规则，变成如果你掷出3或7以外的任何点数，你必须重新掷骰。在这种情况下我们不需要使用该值，所以我们可以更改代码使用`_`而不是变量名为`other`：

```rust
let dice_roll = 9;
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => reroll(),
}

fn add_fancy_hat() {}
fn remove_fancy_hat() {}
fn reroll() {}
```

这个例子同样满足了穷尽性要求，因为我们在最后一个分支里明确忽略所有其他值；我们没有忘记任何东西。

如果我们再次更改游戏规则，使得如果你掷出3或7以外的任何点数，则在你的回合中什么都不会发生，我们可以通过在`_`分支的代码中使用单位值（我们在“元组类型”一节中提到的空元组类型）来表达：

```rust
let dice_roll = 9;
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => (),
}

fn add_fancy_hat() {}
fn remove_fancy_hat() {}
```

在此，我们明确告知Rust，我们不会使用任何不匹配先前分支模式的其他值，并且在这种情况下我们也不想运行任何代码。
