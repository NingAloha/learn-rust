## 使用字符串存储 UTF-8 编码的文本

我们在[关于所有权的章节](course://Understanding Ownership/What is ownership/The String Type)中讨论过字符串，但现在我们会更深入地探讨它们。新手 Rust 用户通常因为三个原因在字符串上卡住：Rust 倾向于暴露可能的错误、字符串作为一种数据结构比许多程序员认为的更复杂、以及 UTF-8。这些因素结合在一起，当你从其他编程语言转过来时，可能显得难以理解。

在讨论集合时讨论字符串是有益的，因为字符串是作为字节的集合来实现的，加上一些方法以提供那些字节被解释为文本时的有用功能。在这一节中，我们将讨论 `String` 上的操作，每种集合类型都有这些操作，比如创建、更新和读取。我们还将讨论 `String` 怎样与其他集合不同，特别是当把人类和计算机对 `String` 数据的解释区别开时，字符串索引为何变得复杂。

### 什么是字符串？

我们首先定义一下我们所说的_字符串_。Rust 核心语言中只有一种字符串类型，即通常以借用形式出现的字符串切片 `str`。在“理解所有权”章节中，我们谈到了_字符串切片_，它是对存储在其他地方的 UTF-8 编码字符串数据的引用。例如，字符串字面量就是存储在程序二进制文件中的，因此是字符串切片。

`String` 类型由 Rust 标准库提供，而不是内建在核心语言中，它是一种可增长的、可变的、拥有所有权的、UTF-8 编码字符串类型。当 Rust 用户提到 Rust 中的“字符串”时，他们通常指的是 `String` 和字符串切片 `&str` 类型，而不只是其中之一。尽管这一节主要关于 `String`，但在 Rust 的标准库中，两种类型都被大量使用，并且 `String` 和字符串切片都是 UTF-8 编码的。

Rust 的标准库还包含许多其他字符串类型，如 `OsString`、`OsStr`、`CString` 和 `CStr`。库 crates 可以提供更多用于存储字符串数据的选项。你会发现这些名字都以 `String` 或 `Str` 结尾？它们指的是拥有和借用的变体，就像你之前看到的 `String` 和 `str` 类型。这些字符串类型可以以不同的编码存储文本，或者以不同的方式在内存中表示。例如，这一章我们不会讨论这些其他字符串类型；请查看它们的 API 文档以了解如何使用它们，以及每种类型何时合适。
