## 变量和可变性

让我们谈谈简单的变量。

```rust
let x = 5;
```

这是一个 `let` 语句，用于创建一个*变量*。这里是另一个例子：

```rust
let foo = bar;
```

这一行创建了一个名为 `foo` 的新变量，并将其绑定到 `bar` 变量的值。

在 Rust 中，默认情况下变量是不可变的。这是 Rust 为了让你编写安全且易于并发的代码所提供的许多建议之一。然而，你仍然可以选择让你的变量可变。让我们探索一下 Rust 为什么鼓励你更喜欢不可变性和为什么有时你可能想选择放弃它。

当一个变量是不可变时，一旦一个值被绑定到一个名字，你就无法更改那个值。请看 main.rs 文件，它的代码还无法编译：

```rust
fn main() {
       let x = 5;
       println!("x 的值是: {}", x);
       x = 6;
       println!("x 的值是: {}", x);
   }
```

点击**运行**按钮来运行程序。

您应该会收到一条错误信息，如以下输出所示：

```text
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         -
  |         |
  |         首次赋值到 `x`
  |         帮助: 使此绑定可变: `mut x`
3 |     println!("x 的值是: {}", x);
4 |     x = 6;
  |     ^^^^^ 无法两次赋值给不可变变量
```

此示例展示了编译器如何帮助您发现程序中的错误。尽管编译器错误可能令人沮丧，但它们仅意味着您的程序还没有安全地执行您想要的操作；并不意味着您不是一个好程序员！在 Rust 社区中，有经验的开发者仍会遇到编译器错误。

错误信息表明，错误的原因是您`无法两次赋值给不可变变量 x`，因为您试图给不可变的 x 变量赋一个第二个值。

当我们试图改变一个我们之前指定为不可变的值时，在编译时出现错误是很重要的，因为这种情况可能导致错误。如果代码的一部分运作是基于一个值永远不变的假设，而代码的另一部分更改了该值，那么代码的第一部分可能无法按设计进行。尤其是在代码的第二部分有时才会更改这个值时，这种错误的原因可能很难追踪。

在 Rust 中，当您声明一个值不会改变时，编译器确保它真的不会改变。这意味着当您阅读和编写代码时，您无需跟踪值可能如何和在哪里改变。因此，您的代码更容易推理。

但可变性可能非常有用。变量默认是不可变的；您可以通过在变量名前添加 `mut` 使它们可变。除了允许更改此值，`mut` 还向未来的代码阅读者传达意图，表明代码的其他部分将更改这个变量的值。

例如，让我们将 _src/main.rs_ 修改为以下内容：

```rust

fn main() {
    let mut x = 5;
    println!("x 的值是: {}", x);
    x = 6;
    println!("x 的值是: {}", x);
}
```

现在运行程序，我们得到以下结果：

```text
$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished dev [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/variables`
x 的值是: 5
x 的值是: 6
```

当使用 `mut` 时，我们可以将 `x` 绑定的值从 `5` 改为 `6`。在某些情况下，您可能希望让一个变量可变，因为这样比仅使用不可变变量更方便编写代码。

除了防止错误，还有许多权衡要考虑。例如，在使用大型数据结构的情况下，就地修改实例可能比复制和返回新分配的实例更快。对于较小的数据结构，创建新实例并以更具函数性编程风格书写可能更易于理解，因此为了获得清晰性，较低的性能可能是值得的代价。
